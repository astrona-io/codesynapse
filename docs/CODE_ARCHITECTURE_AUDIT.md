# Code architecture audit: phase 4j

Assessment completed 2026-10-23 against `ddf78a3ce7bcddd4f162d3af70b99d183ce86eb0`, after phase 4i. This change adds reproducible tests, measurements and an upgrade roadmap. It does not implement the proposed production fixes or approve dependencies.

Keep native Go type analysis, graph-based context selection and the existing store boundaries. Address generated-edit validation and final prompt limits first. Profiles justify improving structural-parser and in-memory search allocations; they do not establish that replacing the stack would improve production latency.

Working assumptions are batch indexing/MCP retrieval and a pure-Go default. The operator was asked about live editing, CGo, repository sizes and resource targets; those requirements remain unconfirmed. Live-editor support, new languages and native dependencies are conditional projects. The synthetic workloads below cannot establish a production SLA or capacity limit.

### Reproduced correctness gaps

The `TestAudit*` cases document current limitations, including undesirable behavior. They are assessment baselines, not acceptance of that behavior: the follow-up fixes must replace those expectations with explicit rejection or correct recovery.

- **Malformed Go:** incomplete declarations and bodies retain useful symbols and valid siblings. Package diagnostics mark affected file stages failed, even when partial symbols survive. This is useful batch recovery, not a live-editor guarantee.
- **Malformed Python/TypeScript:** partial declarations may survive, but an unterminated Python multiline string or TypeScript block can hide later declarations without syntax diagnostics. A foreign `save()` receiver can resolve to an unrelated sole local method by name. Such edges need an inferred-confidence label.
- **Call precision:** typed static and generic calls resolve. Function-variable calls do not; assigned function references remain. Interface implementation edges are candidates rather than proven runtime targets.
- **Diff metadata:** rename-only input produces no changes. Git-quoted tab paths remain escaped instead of matching filesystem paths. Repeated equal text in distinct hunks retains separate line positions. An oversized line fails the whole parse; the existing comment describes different behavior. Hunk arithmetic also needs checked bounds (source inspection, not a measured overflow exploit).
- **Generated edits:** invalid Go, removed copyright and unrelated function replacement pass the current plausibility check. Multiple fenced blocks can be concatenated with intervening prose. A malformed rewrite and a review/base revision mismatch both reach the test runner's fake push callback. These tests use local fixtures and fake providers/pushes; no branch is published by them.
- **Prompt limits:** callers use byte approximations, and some task assembly accepts a first oversized part. Central output limits do not prevent an oversized final input. Provider-reported token usage and configured-price accounting already distinguish known from unknown usage and should remain authoritative for billing.

Evidence is in [`golang/audit_test.go`](../internal/ingest/golang/audit_test.go), [`lang/audit_test.go`](../internal/ingest/lang/audit_test.go), [`audit_diff_test.go`](../internal/gitx/audit_diff_test.go) and [`audit_rewrite_test.go`](../services/api/internal/fixes/audit_rewrite_test.go).

## 2. Measurements and practical limits

[Raw artifacts and reproduction commands](benchmarks/phase4j/README.md) record corpus hashes, policy fingerprints and harness hashes. Hardware: Apple M5 Pro, 48 GiB RAM, darwin/arm64, Go 1.27.3, Git 2.56.0. Runs use one request at a time, without the race detector. Indexing/context/retrieval use `GOMAXPROCS=4`; parser/diff microbenchmarks use the machine default of 18. Numbers from different harnesses must not be combined into an end-to-end estimate.

### Full extraction and publication to the memory adapter

The generated repositories contain Go, Python, TypeScript, YAML and Markdown. Twenty samples per unchanged/edited series give nearest-rank p50/p95. Prior identity evidence is retained; extraction and graph replacement are repeated. No policy file means an empty effective policy digest and no configured exclusions.

| Corpus | First run, ms | Unchanged p50 / p95, ms | One-file edit p50 / p95, ms | Mean allocated per unchanged run |
|---|---:|---:|---:|---:|
| 51 files, 4,939 bytes, 224 nodes / 223 edges | 99.40 | 58.78 / 65.28 | 63.58 / 76.32 | 9.96 MB |
| 501 files, 50,209 bytes, 2,204 nodes / 2,203 edges | 155.97 | 124.39 / 131.11 | 130.34 / 167.66 | 96.02 MB |

These are small synthetic source bodies, even in the larger file-count case. First-run filesystem/toolchain cache state is unknown; it is not a cold-start benchmark. The profiled test process reached 59,621,376 bytes maximum RSS (56.9 MiB). Allocation counters exclude `go list` child heaps; this RSS observation is not an aggregate child/native-memory capacity measurement. Remote graph stores, authentication, models and network publication are excluded.

Across all 82 runs, sampled allocation space was 4,313 MB, including `Graph.Nodes` at 27.79% flat, `docs.addDocument` at 6.42% flat, memory `ReplaceRepo` at 20.93% cumulative and identity reconciliation at 6.72% cumulative. These are cumulative allocations, not live heap; the whole-process profile also includes fixture construction and graph assertions outside the timed section. The memory adapter copies data; its profile does not describe Neo4j/HugeGraph publication. Repeated graph materialization deserves a prototype before increasing workers.

Ranges are benchmark run means, not request percentiles. The TypeScript CPU profile attributes 72.51% cumulative samples to regexp backtracking and 6.16% flat to the parser's line-owner search. Concurrent contention and native parser memory were not measured.

### Token reduction and retrieval

Reusing the phase 4f harness retained all required fixture evidence. Raw input was 3,108 estimated tokens and returned graph/MCP context was 4,523: `(3108 - 4523) / 3108 * 100 = -45.53%`, an expansion. Tiny files are smaller than the response metadata. There is no measured positive savings claim for this corpus.

The existing 5,000-name BM25 workload measured p50/p95/p99 of 4.587/4.799/4.851 ms over 100 samples. This remains below ADR 0001's 50 ms migration trigger. Successful-task warm totals span 0.0124–0.0989 ms at p95, but use in-process synthetic graph/vector inputs. They exclude authenticated HTTP, local embedding execution and remote fetches; they do not validate semantic embedding accuracy or a production SLA. Neo4j/HugeGraph lexical recall currently fetches the bounded namespace population before ranking in Go. Measure that fetch separately before deciding on native Milvus BM25/RRF.

| AST/reuse evidence | Local source search, tests and offline graph review | Adequate for assessment/test additions; disclose fallback before major production changes |

Reconnect the existing CodeSynapse HTTP integration with the supported runtime identity bridge before major graph-assisted work. An optional [official Git MCP server](https://github.com/modelcontextprotocol/servers/tree/main/src/git) exposes status/log/diff and also write tools; use a trusted repository restriction and client-enforced tool allowlist if read-only access is intended. Its documentation describes early development, so verify the installed version and capabilities. Do not assume a built-in read-only switch or install it implicitly. CodeSynapse supplies the symbol/context side; an external LSP-backed service needs a separate capability, licence and data-access review.

Worked reuse example: the indexing harness searches and reuses `policyFiles`, `ingest.Run`, `ingestreport.New/Prepare/Finish`, identity reconciliation and memory `ReplaceRepo`; it does not introduce a second extraction pipeline. Context tests reuse `agentctx.Service` and the existing phase 4f retrieval harness. Diff tests reuse `ParseDiff`, `fixContext`, `setup` and the fake push callback. These modules were queried locally, not via MCP.

The [agent guide](AGENT_GUIDE.md#capability-and-freshness-check-before-editing) now specifies health/freshness checks, search before implementation, reuse and the unavailable-tool path. Its acceptance scenarios cover missing tools, unhealthy services, stale evidence, missing identity and foreign scope. Current environment observation exercises the missing-tools/identity path; the other connection scenarios are manual acceptance procedures, not claimed live results. Existing `TestRuntimeHTTPBindingAndRevocation` covers missing/forged/cross-tenant identity and revocation in an isolated MCP test server.
